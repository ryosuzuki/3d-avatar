2. Animate in Mixamo

Sign in at mixamo.com. The fastest route is Characters → Remy → Use this character. To try an existing FBX instead, click Upload Character and select the downloaded FBX. A compatible pre-rigged FBX skips marker placement. If an unrigged model opens the auto-rigger: face forward → Next → place chin, wrist, elbow, knee and groin markers → Next → review the rig. A failed auto-rig does not improve by waiting indefinitely; use the verified built-in character route.

Then Animations → search “Hip Hop Dancing” → click an animation card. Download → FBX for Unity, With Skin, 30 FPS, Keyframe Reduction: none. For later animations on the same skeleton you may choose Without Skin.

12-second genuine Mixamo screen recording: Remy performing Hip Hop Dancing. This is not a generated illustration.

3. Play it in Unity

Download your animated FBX from Mixamo. Drag it into Unity’s Assets as Character.fbx. Select it → Inspector → Rig → Animation Type: Humanoid → Avatar Definition: Create From This Model → Apply. In Animation, enable Loop Time → Apply.

Create an Animator Controller in Assets, open its Animator window and drag the FBX animation clip into the graph. Drag the character into the Scene. Assign the controller to its Animator component. Turn Apply Root Motion off for an in-place classroom demonstration, then press Play.

Why the earlier avatar looked different

Neural MP4: LHM++ uses model-specific refinement to render an image sequence. Gaussian PLY: exports splats, not that complete renderer. OBJ / GLB proxy: approximates splats with a surface mesh and baked colors. Lost geometry and texture detail do not return when imported into Unity, WebXR or Mixamo. Auto-rigging adds bones, not facial detail.

WebXR route: export your animated FBX from Blender as GLB, with skinning + animation enabled. Load with Three.js GLTFLoader, then use AnimationMixer to play clips. Request an immersive-ar session over HTTPS on a supported device; model playback in a normal browser is not an AR-device test.
